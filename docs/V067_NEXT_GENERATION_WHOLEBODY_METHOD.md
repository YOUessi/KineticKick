# 全身相位协调控制方法接口（v67，未训练、未获得GPU网格证据）

严格区分三件事：**真实人类时序先验**、**机器人真实可执行动作变化**、
**原生几何/碰撞安全证据**。既有 v63 的 0.075rad 合成协同相位可在原 G1 物理
中产生非零20ms动作，但它并非人体训练模型。v64 由 CMU 光学相位拟合，
却因时间支撑没有交集而真实原 G1 八次零激活。v67 验证前者的
“同幅值时间顺序与反序”负对照，不将其视作人体运动论文终点。

未来执行方法：人体 120Hz 多人高质量触球/承重监督 -> encoder 学习
时序 **heel plant → support shift → hip/waist torque → arm counter-swing →
swing-leg instep acceleration → followthrough → 14s recovery**。
使用以机器人实际 **支撑足接地事件** 对齐的相位，而非将 CMU 绝对时间戳
直接映射到机器人墙钟；生成 29DoF 全身轨迹与接触阶段条件化的动作约束，
再通过 `tools/stance_safe_temporal_policy_v067.py` 映射为原电机 action。
此接口独立给出 29 关节原顺序检查、四个动力链部位至少非零、
每步 0.006rad slew/全幅 0.075rad、真实 qdot、关节限、双足压力、
实际支撑边缘和碰撞查询，拒绝时完整返回原动作。
这些是**硬接口和保守拒绝规则**，不是 CBF/MPC 安全证书，更不是
已经学得人类动能链规律。测试使用人为合成数值，绝不冒充真实 PhysX。

**关键阻塞**：目前 GPU 原 G1 左腕—左髋只有同方向反号聚合传感净力、
没有 shape-level 真实 collider manifold/clearance；v58 CPU 原生
骨盆—右髋接触点是真实的 **CPU** 证据，却不能迁移为原 CUDA G1真值。
因此当前接口上机必须 fail closed，缺少 `NativeGeometryWitness`
即使原运动效果“好看”也不得启用。支持足 polygon 及实时 CoP/ZMP
亦尚未完整认证，不能把质心标记的点位直接叫做动态支撑边缘。

待人类专业接触监督和真实 GPU 几何证据满足条件后，拟采用两级训练
（监督学时序协调 → IsaacLab 以完整人体风格、近端到远端时滞、
正脚背碰撞冲量/出球速度、站稳恢复/非脚事件联合强化学习），在
**独立预留人/动作/球位** 上对 v32、反向/乱序相位和完全移除人体先验做
盲控比较；触球合法性≥95%、3.5m/s、29 qdot、完整14s及球门为
不能因自然性单指标高而取消的 **硬门禁**。无GT前不执行“职业强射已学成”的声明。
