# Controller baseline compatibility — read-only audit, 2026-11-07

The currently reusable execution backend is the local PAiD/running expert stack, including the v32 post-shot residual. BeyondMimic supplies a closely related, licensed tracking implementation, but no working independent BeyondMimic soccer baseline has been established here. SuperMimic remains a paper-level candidate: its official page and paper did not provide a verified, licensed training-code/checkpoint entry point in this audit. None of these findings completes a paper comparison or resolves the human-kick data qualification gap.

This audit read local source/configuration and two methods' official materials. It did not launch Isaac, import simulator-dependent modules, run inference/training/GPU work, install dependencies, fetch robot assets, or change repository files. The audit was performed independently of the v34 control experiment.

The local PAiD sample was inspected with NumPy, without importing simulator code: `soccer-standard-001_right.npz` has `fps=[50]`, `joint_pos/joint_vel=(260,29)`, `body_pos_w/body_lin_vel_w/body_ang_vel_w=(260,30,3)`, `body_quat_w=(260,30,4)`, and scalar `kick_leg`. Quaternions follow the local `wxyz` contract, lengths are metres and angles radians. Array slots have no embedded joint/body-name arrays; match them to the actual runtime/ONNX order, not lexical URDF order. Both pinned loaders consume this same core array family; PAiD adds padded multiple-motion lengths and kick-side metadata. Both command loops increment an integer frame each control step; reading `fps` does not perform automatic resampling. A 25 Hz human sequence cannot be supplied unchanged to a 50 Hz loop.

Both trackers use torso anchor and 14 selected bodies for task-space errors. BeyondMimic aligns relative body targets to current robot anchor XY/yaw while retaining reference height; this is not the same metric as absolute world-trajectory error. Human marker geometry, uncertainty masks, reconstructed joints and coarse events from P2 do not directly satisfy the robot generalized-coordinate/FK contract. A validated conversion and dynamics-aware generation interface is still absent; merely renaming an NPZ is invalid.

**Robot and contact comparability**

The two pinned `robots/g1.py` files differ only in the asset-module import. Both specify a free base, enabled self-collision, cylinder-to-capsule conversion, implicit PD actuators, 10 Hz natural frequency, damping ratio 2, and `q_setpoint = q_default + action_scale * action`, where `action_scale = 0.25 * effort_limit / stiffness`. The action is a low-gain torque-producing setpoint, not a directly attained joint angle. Soft joint-position factor is 0.9. Both default environments use four 5 ms substeps per 20 ms policy step.

| Actuator group | Effort limit, Nm | Velocity limit, rad/s |
|---|---:|---:|
| Hip pitch/yaw; waist yaw | 88 | 32 |
| Hip roll; knee | 139 | 20 |
| Ankle pitch/roll; waist pitch/roll | 50 | 37 |
| Shoulder axes, elbow, wrist roll | 25 | 37 |
| Wrist pitch/yaw | 5 | 22 |

The PAiD source `main.urdf` and `configs/paid_original/main.urdf` are 40,589 bytes, SHA-256 `dbc8471004e9b0b85c27a4ebc1f0d90a727c1cf7ca9ef507b805596f2004d64b`, with 29 movable joints. BeyondMimic's corresponding asset is missing, so collision meshes, inertia and exact joint ordering cannot yet be cross-checked. Matching actuator source is useful evidence, not full physics parity. [Actuator source](/home/you/projects/kinetickick/third_party/HumanoidSoccer/source/whole_body_tracking/soccer/robots/g1.py:7).

PAiD soccer adds a ball, destination and ball-contact/speed/direction reward terms. Standard BeyondMimic tracking has ground/self-contact machinery for rewards, but no equivalent ball-task actor observations or objective. Current local control goes further: actual pair-filtered ground forces, capsule heights and collision/ball separation evidence drive decisions; the evaluator also replaces reference-error terminations with physical height/orientation/non-foot criteria. These choices must be disclosed. A tracker scored on clip survival and a shooter scored on contact surface, outgoing ball direction/speed and recovery answer different questions. [Soccer observations](/home/you/projects/kinetickick/third_party/HumanoidSoccer/source/whole_body_tracking/soccer/tasks/tracking/config/g1/soccer_flat_env_cfg.py:32), [physical evaluation termination overrides](/home/you/projects/kinetickick/tools/run_placement_strike.py:40).

**Fair-experiment boundaries for the next work**

- Separate reference-generation effects from backend effects. A useful controlled P3 comparison can retain the same physical model, pretrained expert checkpoints and observation permissions while changing the declared generator. Call that a local backend-controlled comparison, not BeyondMimic/SuperMimic reproduction.
- Pin robot source, processed asset, joint/body order, actuator gains/scales/limits, collision geometry, ball mass/material, friction, physics solver and substeps. Do not compensate for one method by widening limits or substituting the latest simulator under the same method name.
- Report ball/goal availability, measured versus privileged body/force signals, reference lookahead, observation history and recurrence separately. A 160-value vector is not a portable contract. Shared information can be used for an ablation only if the resulting baseline modification is explicitly named.
- Freeze reference provenance, training/reference coverage, initial state/phase distribution, randomization and test perturbations. Ground-truth human contact, joint centers and professional instep labels remain unresolved; retargeted robot arrays cannot certify them.
- Use identical task outcomes and an independent physical evaluator for shooting: first contact body/surface, ball impulse and direction/speed, goal outcome, complete recovery, slip, collision and joint-speed/effort violations. Report tracking error separately; do not translate each paper's native survival criterion into common success.
- Record inherited pretraining, new training, all candidate runs, adaptation fitting, evaluation and inference separately. Report GPU model/count, elapsed time, control/physics samples and optimization updates; SuperMimic also needs imagined-sample counts. Retain failures and the fixed checkpoint-selection rule.

Practical status: local motion/metadata adapters, recurrent experts, contact recorder and physical acceptance logic are reusable now. BeyondMimic source is a credible independent **tracking** baseline candidate after asset/interface parity and actual training/evaluation; those steps have not been performed. SuperMimic cannot yet be scheduled as a reproducible official baseline from the verified artifacts.
